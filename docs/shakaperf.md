# Local ShakaPerf integration

This optional development check compares the current Inertia product landing page with a pinned upstream control. It changes no application behavior and introduces no production dependency. The initial comparison is an A/A calibration, not an optimization experiment.

From this branch, with the repository's Ruby and Node versions, Bundler dependencies, a root npm ci install, Docker Compose, Python 3, cc and c++ compiler tools, Google Chrome and the locked Playwright Chromium browser available, run:

```sh
bin/shakaperf-local
```

Commit tracked changes and remove any repository-root `.env` before running: the tool eagerly loads it, and the launcher rejects it before setup. The command creates clean detached control at upstream `921e1d56e1685084b66cb4a532439e4b3069de4c` and experiment at committed `HEAD`, independent Docker projects/databases, a synthetic seller and a $10 product, and two local Rails servers. Both snapshots receive fresh locked npm installs and independent builds; ignored snapshot dotenv, credentials and build outputs are excluded. Only PATH, HOME, TMPDIR, Ruby gem paths, BUNDLE_PATH and an optional CHROME_PATH are inherited. The source diff disables external diff drivers. It builds Vite assets, installs the tool lock, and starts ShakaPerf **0.3.1**. Install its Chromium build once with `tools/shakaperf/node_modules/shaka-perf/node_modules/.bin/playwright install chromium` after `npm ci --ignore-scripts --prefix tools/shakaperf`. The lock freezes Playwright1.58.2, Lighthouse13.4.1 and their dependencies. Published tool source is `2c5753f7bf960c3890018b7719d631ee1fdddb6f`; npm integrity is retained. The scenario pins shared0.3.0; the application uses upstream React18.3.1/Inertia2.3.13, with no Pro/RSC dependency.

Ports 3411/3412 serve Rails; Vite ports 3511/3512 remain unused. The command also reserves local MySQL 3331/3332, Redis 6401/6402, DynamoDB 8041/8042, Elasticsearch 9241/9242, and MinIO 9041/9042 and 9051/9052. Occupied ports fail the setup. Owned Rails process groups are stopped and disposable Docker volumes are removed on exit. On interruption, inspect and stop any remaining active build/comparison child before restarting; the launcher does not signal that system child. Both checkouts and evidence remain under `tmp/shakaperf-local`. Preserve evidence before removing that checkout with `git worktree remove tmp/shakaperf-local/control` and likewise removing tmp/shakaperf-local/experiment and then removing the remaining state directory for another campaign.

The performance target starts directly at the canonical `shakaperf.localhost` seller origin; the runner requires navigation to stay on that origin. The page scenario awaits the product title, description, purchase link and Inertia component identity. It records attempted local requests, successful HTTP responses, completed response bodies, console errors and uncaught page errors, and rejects failed local requests, HTTP errors or uncaught page errors. Console errors remain visible evidence: development Bullet emits a CSP warning. The fixture consumes a clone and independently awaits a success marker for the real body, even if the app catches a failure; it validates a clone of the real product-view analytics JSON response: upstream leaves that body unread, which prevented Chromium network idle in diagnostics. Google Analytics and Tag Manager requests receive identical empty 204 responses on both sides and are counted as intentional exclusions; this does not test third-party analytics. Routing disables the browser HTTP cache, consistent with the cold-navigation workload. Visual comparison covers the product article in desktop and phone viewports, and accessibility comparison reports the existing page's findings. These checks do not exercise a purchase or establish full checkout correctness.

Performance uses **18 simultaneous control/experiment pairs per viewport**, serial viewport execution, no retries, native paired statistics, a .05 p-value threshold and a **5ms absolute timing regression threshold** using the estimator. Earlier prose incorrectly called this5%; the numeric configuration is unchanged. DevTools throttling uses200ms request latency,2700kbit/s throughput and3x CPU slowdown. Diagnostic profiles remain separate from statistical samples. FCP/LCP are navigation-relative Lighthouse paint times. Awaited content checks do not turn those metrics into full interaction durations.

A green comparison indicates its configured checks passed; it does not prove a speedup or equivalence.

Rails runs in **development mode with prebuilt Vite assets**. Reloading, development middleware, browser throttling, a single synthetic product and shared machine contention limit interpretation. This is a local integration check, not a production architecture comparison. The command captures source identity, dirty state, file hashes, tool/runtime versions, effective environments and machine load. Synthetic external IDs and CSP nonces are generated independently; only product content, price and seller identity are fixed. Retain all failures and samples rather than rerunning for a preferred outcome.

The frozen optional tool tree reports eight npm dependency advisories, including two critical classifications. Tool installation disables general npm lifecycle scripts and explicitly compiles the pinned ShakaPerf socketpair addon with locked node-gyp; Python 3, cc and c++ are required and selected explicitly before setup. It checks the native socket pair before comparison and records the installed node-gyp version, selected Python/CC/CXX executables and their versions, source and binary identities. install the prerequisite browser explicitly before capture. Source inspection found the vulnerable Handlebars compiler in the legacy report path and the Express/proxy-address parser in a separate server command; neither is invoked by this compare command. Sharp is reached for browser-produced raster images; this fixture supplies no SVG input to it. These observations bound this owned, loopback capture and do not establish security clearance for remote targets, imported artifacts, installation or broader adoption. Keep this lock for evidence reproduction; defer broader adoption until a separate tool dependency refresh and audit, prioritizing Sharp and Handlebars. No advisory is fixed by this integration.
