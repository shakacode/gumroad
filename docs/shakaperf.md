# Local ShakaPerf integration

This optional development check compares the current Inertia product landing page with a pinned upstream control. It changes no application behavior and introduces no production dependency. The initial comparison is an A/A calibration, not an optimization experiment.

From this branch, with the repository's Ruby and Node versions, Bundler dependencies, a root npm ci install, Docker Compose, Python 3, native compiler tools, Google Chrome and the locked Playwright Chromium browser available, run:

```sh
bin/shakaperf-local
```

Commit tracked changes before running. The command creates clean detached control and experiment worktrees at upstream `921e1d56e1685084b66cb4a532439e4b3069de4c`, independent Docker projects and databases, a synthetic seller and a $10 product, and two local Rails servers. Both snapshots receive fresh locked npm installs and independent builds; ignored local dotenv, credentials and build outputs are excluded. Only PATH, HOME, TMPDIR, Ruby gem paths, BUNDLE_PATH and an optional CHROME_PATH are inherited. The source diff uses Git with external diff drivers disabled. It builds Vite assets, installs the tool from `tools/shakaperf/package-lock.json`, and starts ShakaPerf **0.3.1**. Install its Chromium build once with `tools/shakaperf/node_modules/.bin/playwright install chromium` after `npm ci --prefix tools/shakaperf`. That tool lock freezes its transitive dependencies, including Playwright 1.58.2 and Lighthouse 13.4.1. The published tool source is `2c5753f7bf960c3890018b7719d631ee1fdddb6f`; the lock retains its npm integrity hash. The scenario uses `shaka-shared` **0.3.0**, pinned in the lockfile. The application uses upstream React 18.3.1 and Inertia 2.3.13; there is no Pro or RSC dependency.

Ports 3411/3412 serve Rails; Vite ports 3511/3512 remain unused. The command also reserves local MySQL 3331/3332, Redis 6401/6402, DynamoDB 8041/8042, Elasticsearch 9241/9242, and MinIO 9041/9042 and 9051/9052. Occupied ports fail the setup. Owned Rails process groups are stopped and disposable Docker volumes are removed on exit. On interruption, inspect and stop any remaining active build/comparison child before restarting; the launcher does not signal that system child. Both checkouts and evidence remain under `tmp/shakaperf-local`. Preserve evidence before removing that checkout with `git worktree remove tmp/shakaperf-local/control` and likewise removing tmp/shakaperf-local/experiment and then removing the remaining state directory for another campaign.

The performance target starts directly at the canonical `shakaperf.localhost` seller origin; the runner requires navigation to stay on that origin. The page scenario awaits the product title, description, purchase link and Inertia component identity. It records attempted local requests, successful HTTP responses, completed response bodies, console errors and uncaught page errors, and rejects failed local requests, HTTP errors or uncaught page errors. Console errors remain visible evidence: development Bullet emits a CSP warning. The fixture consumes a clone and independently awaits a success marker for the real body, even if the app catches a failure; it validates a clone of the real product-view analytics JSON response: upstream leaves that body unread, which prevented Chromium network idle in diagnostics. Google Analytics and Tag Manager requests receive identical empty 204 responses on both sides and are counted as intentional exclusions; this does not test third-party analytics. Routing disables the browser HTTP cache, consistent with the cold-navigation workload. Visual comparison covers the product article in desktop and phone viewports, and accessibility comparison reports the existing page's findings. These checks do not exercise a purchase or establish full checkout correctness.

Performance uses **18 simultaneous control/experiment pairs per viewport**, serial viewport execution, no retries, native paired statistics, a .05 p-value threshold and a 5% practical regression threshold using the estimator. DevTools throttling uses 200ms request latency, 2700kbit/s throughput and 3x CPU slowdown. The config is the effective contract; diagnostic profiles are separate from statistical samples. FCP/LCP are navigation-relative Lighthouse paint times. Awaited content checks hold collection open but do not turn those metrics into full interaction durations.

Preserve `compare-results`, including its HTML report, statistical per-test `report.json`, `ab-measurements.json`, diagnostics and logs, along with `tmp/shakaperf-local/provenance.json`. Each test/viewport directory stores numerical data under `artifacts/report.json` and `artifacts/ab-measurements.json`. Raw time samples encode microseconds despite the `ms` label; statistical reports convert them to milliseconds. Transfer labels use bytes/1024 (KiB). The top-level compare `report.json` can have empty metric summaries: read the HTML and per-test numerical artifacts before stating any estimate or confidence interval. A green comparison indicates its configured checks passed; it does not prove a speedup or equivalence.

Rails runs in **development mode with prebuilt Vite assets**. Reloading, development middleware, browser throttling, a single synthetic product and shared machine contention limit interpretation. This is a local integration check, not a production architecture comparison. The command captures source identity, dirty state, file hashes, tool/runtime versions, effective environments and machine load. Synthetic external IDs and CSP nonces are generated independently; only product content, price and seller identity are fixed. Retain all failures and samples rather than rerunning for a preferred outcome.

Before interpreting a result, record its claim and inspect: (1) diagnosed limiter, (2) build/runtime tuning and parity, (3) physical plausibility and units, (4) failed and successful work, (5) source/tool identity, pairing and all numerical artifacts, (6) user relevance, and (7) the timer boundary and awaited work. Missing evidence narrows the conclusion. Consumer guidance is tracked in [ShakaPerf #36](https://github.com/shakacode/shakaperf/issues/36), numerical summaries in [#68](https://github.com/shakacode/shakaperf/issues/68), and schema/provenance in [#69](https://github.com/shakacode/shakaperf/issues/69). This procedure adds no repository verification gate.

The frozen optional tool tree reports eight npm dependency advisories, including two critical classifications. Tool installation disables general npm lifecycle scripts and explicitly compiles the pinned ShakaPerf socketpair addon with locked node-gyp 12.1.0; Python 3 and compiler tools are required. It checks the native socket pair before comparison and records source/compiler/binary identities. install the prerequisite browser explicitly before capture. Source inspection found the vulnerable Handlebars compiler in the legacy report path and the Express/proxy-address parser in a separate server command; neither is invoked by this compare command. Sharp is reached for browser-produced raster images; this fixture supplies no SVG input to it. These observations bound this owned, loopback capture and do not establish security clearance for remote targets, imported artifacts, installation or broader adoption. Keep this lock for evidence reproduction; defer broader adoption until a separate tool dependency refresh and audit, prioritizing Sharp and Handlebars. No advisory is fixed by this integration.

The [completed calibration](evidence/shakaperf-inertia-calibration/README.md) retains all18 pairs per viewport, native paired estimates/intervals, work counts, timing identities and article captures. It found no statistically significant FCP/LCP difference. Live Stripe traffic remains unexcluded and unpinned; one phone statistical context recorded an unattributed connection-closed console error while every counted local request completed. These limits prevent a claim of complete external success or identical cross-run conditions.
